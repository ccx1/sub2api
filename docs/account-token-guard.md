# 账号凭证守护（智能运维 → 凭证守护）

面向 OpenAI OAuth 账号的令牌健康巡检与自愈能力，作为「智能运维」下的子页面提供：

- 页面路径：`/admin/token-guard`
- 接口前缀：`/api/v1/admin/account-ops/token-guard/*`
- 默认关闭。保留本站授权（builtin）和外站桥接（external）两种模式；旧配置沿用原模式，不自动切换授权来源。外站模式需由管理员确认测活与重登端点及请求头。

## 工作方式

1. **定时巡检**：按配置间隔用账号当前的 `access_token` 调用「测活接口」，结果分为 `正常`、`令牌失效`、`临时异常`。
2. **令牌失效自愈**：命中失效且开启自动重登时，用配置的 `邮箱 + 密码 + 2FA 密钥` 调「重登接口」换新凭据，随后按原账号版本条件写回凭据（保留 `model_mapping` 等字段）、清错误态、更新调度快照并失效服务端 token 缓存。已有 `schedulable=false`、限流和临时保护保持不变。
3. **账号范围**：通过守护专用查询选择 `active` 和 `error` 状态的 OpenAI OAuth 账号，并遵守配置的分组范围。排除已删除、非 OAuth、影子账号及已过期且要求自动暂停的账号；`inactive`/`disabled` 不参与恢复。不放宽通用账号列表或业务调度查询。
4. **可观测**：账号最近一次探活结果与巡检/修复日志全部落库，页面展示并支持单账号手动重登。

## 配置项

| 字段 | 说明 |
| --- | --- |
| 启用守护 | 关闭后不做任何巡检与修复 |
| 守护分组 | 留空表示专用查询范围内的 active/error OpenAI OAuth 账号；支持搜索与多选分组 |
| 巡检间隔 / 超时 / 并发 / 每轮上限 | 站点测活较慢时用「每轮上限」控制单轮规模，未覆盖账号下一轮优先 |
| 测活接口 / 测活模型 | 默认指向参考服务 session.ameng2027.xyz 与 gpt-6-astra，可替换 | `POST {probe_endpoint}`，请求体 `{"access_token": "...", "model": "..."}`，按 NDJSON 返回 `{"type":"result","payload":{...}}` |
| 测活 / 重登 额外请求头 | 每行一个 `Header-Name: value`；值里可用 `{{uuid}}` 生成每次请求唯一的随机串；接口协议要求由配置提供，代码不内置任何第三方标识 |
| 自动重登 / 重登接口 / 重登凭据 | 保留本站凭据表格、TXT/粘贴导入以及停用/到期控制；外站模式接口请求体为 `{"action":"start","email":"...","auth_mode":"password_2fa","password":"...","mfa_secret":"..."}`，返回 `credential` 对象 |
| 修复后的调度设置 | 清除错误态后保留原调度开关和限流保护；人工停用仍需人工恢复，旧 `restore_schedulable` 字段仅保留配置兼容 |
| Bark Key / 推送开关 | 可选，修复成功或失败时推送通知 |

## 数据表

- `account_token_guard_states`：每个账号最新巡检状态（探活结果、延迟、连续失效次数、最近修复）。
- `account_token_guard_events`：巡检与修复日志，保留最近 14 天。

## 安全说明

- 巡检只读取账号已有的 `access_token`，不会主动修改账号凭据。
- 仅在「令牌失效且开启自动重登」时写回新凭据，并保留账号既有配置字段。
- 重登凭据保存在管理员设置中，请只在自建环境填写；对外共享数据库前建议先清空该字段。

## 后台巡检与可靠性

- 手动巡检通过后台任务执行，按任务 ID 查询进度并支持取消；查询不存在或连续失败时页面结束等待并显示原因。旧同步接口保留兼容。
- 分批巡检保留未选中账号的历史，按最近探活时间轮转；进度写入不再清零连续失败计数。状态读取或写入失败会明确报告。
- 外站接口的 HTTP 错误归为临时故障，仅明确业务失效码触发重登；JSON/NDJSON 收到完整结果后即可返回，不等待 EOF。本站直接测活继续按实际认证状态分类。
- 本站探活/重登继承任务取消和时间预算；固定代理加载失败不会静默直连，随机代理复用现有选择与空池策略，运行时关联不写成固定代理。
- 凭据停用、到期控制及 builtin/external 模式均保留。首次 2FA 外站登录导入未接入本地版本。
- 同一服务进程中，手动重登与自动巡检/修复使用同一账号级互斥控制；同账号正在处理时返回忙或跳过，其他账号仍可并行。锁覆盖处理到状态落库，失败、取消及服务停止后释放。
- 凭据修复在数据库中原子比较账号 `updated_at`、原凭据、状态、调度开关和代理关联；条件不再匹配时丢弃旧结果。账号更新与 scheduler outbox 写入在同一语句提交，成功后刷新调度快照及 token 缓存。
- 巡检状态落库同时验证账号快照和守护状态版本；旧探活结果不能覆盖较新的手动重登或另一轮状态。版本冲突不记为新的凭据失效，也不会重试写入旧凭据。
- `restore_schedulable` 字段保留配置兼容；守护不会把 `schedulable=false` 改成 `true`，也不清空既有的限流或临时保护。原本可调度的 error 账号清错后按现有调度规则重新评估，人工停用仍需人工恢复。
- 账号锁只在当前进程内去重；多实例依靠数据库条件写入防止旧结果覆盖，不保证跨实例只发起一次外部登录。外站及本站真实账号行为需要在专用测试环境另行验收。
