# 后台初始化与基础配置

后台初始化的目标是让系统具备可登录、可调度、可计费、可观察的最小闭环。

## 首次初始化

不同部署方式的初始化入口不同：

- Docker Compose：启用 `AUTO_SETUP=true` 后，系统会按 `.env` 自动初始化。
- 安装脚本或源码运行：首次访问 Web 页面进入设置向导。

初始化至少需要准备：

- PostgreSQL 连接信息
- Redis 连接信息
- 管理员邮箱和密码
- JWT 密钥

Docker 部署中建议固定这些变量，避免重启后登录态或 2FA 失效：

```env
POSTGRES_PASSWORD=change_this_secure_password
JWT_SECRET=replace_with_random_hex
TOTP_ENCRYPTION_KEY=replace_with_random_hex
ADMIN_EMAIL=admin@example.com
ADMIN_PASSWORD=replace_with_strong_password
TZ=Asia/Shanghai
```

可用下面命令生成随机密钥：

```bash
openssl rand -hex 32
```

## 站点基础信息

管理员登录后，进入后台设置页，按实际站点补充：

- 站点名称
- 站点 Logo
- API 基础地址
- 联系方式
- 文档地址
- 注册、邮箱验证、登录协议、Turnstile 等公开开关

用户端“API Key 使用配置”会读取公开设置里的 `api_base_url`。如果这个地址为空，前端会回退使用当前页面域名。

## 上游账号

进入管理后台的账号管理页面，添加真实上游账号。仓库现有功能支持多种平台和授权方式，具体字段以后台表单为准。

常见操作：

- 新增账号
- 测试账号连通性
- 刷新账号状态
- 设置账号是否可调度
- 将账号绑定到分组
- 查看账号今日统计和用量

如果账号测试失败，先区分是凭证问题、代理问题、上游限流，还是运行环境网络问题。

## 分组

分组是用户 API Key 调度的核心边界。管理员需要至少准备一个可用分组，并把上游账号绑定进去。

分组常用配置包括：

- 平台类型，例如 Anthropic、OpenAI、Gemini、Antigravity
- 可绑定账号
- 是否公开或专属
- 倍率
- 并发限制
- RPM 限制
- Claude Code 客户端限制及回退分组
- 订阅分组相关配置

普通用户创建 API Key 后，需要把 Key 分配到可访问分组；没有分组的 Key 不能获得完整客户端配置。

## 渠道与可用模型

渠道用于用户侧展示“我能用哪些平台、哪些分组、哪些模型以及价格”。用户端通过 `/api/v1/channels/available` 获取可用渠道。

管理员应确保：

- 渠道已创建并启用
- 渠道包含正确平台
- 分组和渠道关系清晰
- 支持模型和定价配置完整
- 用户有权限访问对应公开分组、专属分组或订阅分组

## 安全设置

生产环境建议至少确认：

- 站点使用 HTTPS
- `JWT_SECRET` 固定且足够随机
- `TOTP_ENCRYPTION_KEY` 固定且足够随机
- 后台管理员使用强密码
- 反向代理正确传递真实 IP
- URL 白名单按实际上游收紧
- 不在源码或文档中写入真实密钥

使用 Nginx 代理并搭配 Codex CLI 时，在 Nginx `http` 块加入：

```nginx
underscores_in_headers on;
```
