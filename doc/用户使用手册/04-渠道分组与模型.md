# 渠道、分组与模型

Sub2API 的调度和展示由“上游账号、分组、渠道、模型定价”共同决定。

## 关系说明

```text
上游账号 -> 绑定到分组 -> 分组挂到渠道 -> 用户 API Key 选择分组 -> 请求按平台进入网关
```

这几个概念的职责不同：

| 概念 | 作用 |
| --- | --- |
| 上游账号 | 保存真实上游凭证和账号状态 |
| 分组 | 控制调度边界、平台、倍率、限制和可见范围 |
| 渠道 | 用户侧展示入口，聚合平台、分组和模型 |
| 模型定价 | 决定不同模型和计费模式的价格展示与扣费依据 |

## 平台与网关端点

当前仓库的网关路由提供这些主要入口：

| 入口 | 用途 |
| --- | --- |
| `/v1/messages` | Claude Messages 兼容；OpenAI 分组会自动走 OpenAI 消息转换链路 |
| `/v1/messages/count_tokens` | Claude Token 计数；OpenAI 分组返回不支持 |
| `/v1/models` | 模型列表 |
| `/v1/usage` | 当前 API Key 用量查询 |
| `/v1/responses` | OpenAI Responses 兼容；也可自动路由 |
| `/responses` | 不带 `/v1` 的 Responses 别名 |
| `/backend-api/codex/responses` | Codex 专用 Responses 入口 |
| `/v1/chat/completions` | OpenAI Chat Completions 兼容 |
| `/chat/completions` | 不带 `/v1` 的 Chat Completions 别名 |
| `/v1/images/generations` | OpenAI 图片生成，只有 OpenAI 平台分组可用 |
| `/v1/images/edits` | OpenAI 图片编辑，只有 OpenAI 平台分组可用 |
| `/v1beta/models` | Gemini 原生 API 兼容 |
| `/v1beta/models/{model}:...` | Gemini SDK/CLI 调用入口 |
| `/antigravity/v1/messages` | Antigravity Claude 专用入口 |
| `/antigravity/v1beta/...` | Antigravity Gemini 专用入口 |

## 用户侧可用渠道

用户端“可用渠道”页面来自 `/api/v1/channels/available`，展示内容包括：

- 渠道名称和描述
- 平台分区
- 用户可访问的分组
- 分组类型，例如标准分组或订阅分组
- 支持模型
- 定价信息

如果用户看不到某个渠道或模型，通常从这些方向排查：

- 渠道是否启用
- 分组是否绑定到渠道
- 用户是否有权限访问该分组
- 订阅分组是否仍在有效期内
- 模型定价或支持模型是否配置完整

## 模型和价格

模型价格可能按不同计费模式展示，例如 Token 计费、区间计费、图片计费或单次请求计费。用户侧展示会读取后端返回的 `pricing` 信息。

管理员配置模型价格时，建议保持这些信息一致：

- 模型名称与实际上游模型一致
- 平台类型一致
- 输入、输出、缓存读写价格完整
- 图片或单次请求计费字段按实际计费模式填写
- 分组倍率和用户专属倍率不会造成预期外折扣

## Antigravity 分组

Antigravity 有专用端点，避免与普通 Anthropic/Gemini 调度混淆：

```bash
export ANTHROPIC_BASE_URL="https://api.example.com/antigravity"
export ANTHROPIC_AUTH_TOKEN="sk-xxxx"
```

Gemini 客户端使用 Antigravity 时，基础地址应指向：

```text
https://api.example.com/antigravity/v1beta
```

如果启用混合调度，需要特别注意上下文隔离，不要把普通 Anthropic Claude 和 Antigravity Claude 放在同一上下文里混用。
